# AGENTS.md 优化工作说明

本目录中的 `AGENTS.md` 是用户的**全局 AI 协作指引**草稿，供 Obsidian、Amp 等多个宿主共用。本文件记录历次优化形成的共识与约束，接手优化前必须先读完本文件。

## 设计原则（不可推翻，除非用户明确要求）

### 循环分类学：按产物消费者的距离分层

全文的组织核心是一条可迁移的决策规则：**这个产物的最终消费者是谁？他有没有本次对话的上下文？**

| 层 | 章节 | 消费者 | 例子 |
|---|---|---|---|
| 内 | 执行过程 | AI 自己 | 搜索命令、浏览器 session、临时文件 |
| 中 | 及时小循环 | 用户，当场、在对话内 | 交付物、阻塞通知 |
| 外 | 异步大循环 | 他人或他人的 AI，离场、无对话上下文 | 测试、TODO、commit、Issue |

三大节按消费者距离**由近到远**排列。每个循环章节的第一段是 scope 定义句，写明判断标准——这让 AI 能把原则推广到未列举的产物类型（如 PR 描述、commit message）。优化时不得删除 scope 句，不得把循环外的横切规则（语言、授权边界）塞进某个循环。

### 大循环内部按任务时间线排序

测试 → 临时兼容代码（写代码阶段）→ Git 与 GitHub 身份（提交阶段）→ Skill 冲突与反馈（收尾阶段）。

**依赖约束**：「Skill 冲突与反馈」引用「GitHub 多账号」的 token 注入流程（原文「除『Skill 冲突与反馈』一节另有规定外」是反向交叉引用），两节必须保持 Git 在前、Skill 紧随其后。调整顺序时先检查这条引用仍然成立。

### 标题服务检索，幽默放正文

标题必须让 AI 能按语义命中规则；风格化表达（如早期版本的「降低屎山率」）如要保留，放正文不放标题。

### 用 Markdown，不用 XML

XML 标签的价值在程序化抽取和隔离不可信内容；本文件是人手维护、被 LLM 当散文读的指引，「标题 + scope 首句」已足够表达结构，且与 AGENTS.md 生态的 Markdown 惯例一致。不要改成 XML。

## 跨宿主重复是有意的（最容易被误删）

「交付物」一节与部分宿主（如 Amp orb）注入的内置指引重复。**这是有意冗余**：同一份全局指引在多个宿主使用，并非每个宿主都注入这些规则。文内已有 HTML 注释说明；优化时不得以「与系统提示词重复」为由删除，也不得删除那条 HTML 注释本身。

## 术语表（已统一，修改时保持）

| 用 | 不用 | 说明 |
|---|---|---|
| 用户 | 人类 | 指对话中的具体协作者 |
| 仓库 | repo | 例外：`repo-local` 保留英文，是 Git 配置层级的精确术语 |
| 单账号环境 / 多账号 | 单一身份环境 | 保持对称 |
| 本次对话 | 这次对话 | |
| Web Thread / Amp Thread | Web thread | 大小写与「Amp Thread ID / URL」统一 |

**有意区分的近义词，不得合并：**

- **任务 vs 对话**：「任务」是执行单元（授权范围、browser session 隔离按任务划分；一个对话可含多个并发任务）；「对话」是消费边界（大小循环按它划分）。
- **产物 vs 交付物**：「产物」泛指任何输出；「交付物」特指放入 `.amp/in/artifacts/`、供用户当场消费的最终文件。

大循环 scope 句的产物列表不含「push」：push 是动作不是产物，被接手的是 commit 和 Issue。

## 行文规范

- 语言遵循 AGENTS.md 自身「语言」节：直角引号「」，中英文间 1 个半角空格。术语以精确为先，英文更精确时用英文（如 headless、shim、login）。
- 主谓宾完整，避免话题式省略导致歧义。历史教训：「外部写入……执行最小必要动作」（写入变成了执行者）、「不得扩展到相邻对象」（缺宾语「授权」）、「才已授权在完成……后」（动词粘连）——均已修复，不要改回。
- 对 AI 的指令用无主语祈使句或隐含第二人称，不用「AI 可……」这类第三人称描述。

## 已核验的外部事实（不要当作错误「修正」）

以下命令与用法在优化过程中逐一核验过，均正确：

- `git config --show-origin --get user.name` / `user.email`
- `git show -s --format='%an <%ae>%n%cn <%ce>' HEAD`（author + committer 四个格式符）
- `gh auth token --user <login>`：gh ≥ 2.40 多账号功能；`GH_TOKEN` 环境变量对 `gh` 及 `gh auth git-credential` 均优先于 keyring
- `git -c credential.helper= -c 'credential.helper=!gh auth git-credential' push`：空值先清空 helper 列表再追加，标准写法
- `fd --hidden --no-ignore`
- `curl -K -` 从 stdin 读配置，`header = "..."` 是合法 curl 配置语法
- `time-sensitive` 是 APNs interruption level 的正确拼写

`agent-browser` 与 Brrr API（`api.brrr.now`）是用户私有工具，无公开文档可查，按现状信任，不要凭猜测「修正」其用法。

## 待定项（尚未获得用户决定，接手时先确认）

1. **Git 节下的四级标题**（`#### Commit 身份` / `#### GitHub 多账号`）：可读性开始下降，备选方案是改为加粗行内标签。用户尚未拍板。
2. **「阻塞时通知用户」标题**：由「通知人类」改来以统一术语；若用户偏爱「人类」的 human-in-the-loop 意味，可改回，但需连带统一正文。
3. **「浏览器自动化」节迁出为 Skill**：五条规则均为真 invariant，但只在操作网页 UI 时相关，是 progressive disclosure 的理想候选。待用户的 Skill 基础设施在所有宿主可用后迁出，AGENTS.md 留一行指针。

## 已裁决（附理由，防止翻烧饼）

- **保留「授权边界」「执行过程」「文件与路径发现」现状，压缩到此为止**（2026-08）：优化目标是信号纯度而非行数最小化；三层循环的自洽是功能性资产（全文只有「产物的消费者是谁」一个判断逻辑）。后续增删的触发器是观察到的事实——模型违反某条边界则加改，某条规则长期无关且可疑则删——不做无证据的进一步浓缩。
- **删除 GNU Parallel 段、压缩 fd/find 选型细节**（2026-08）：属 how-to 而非 invariant，场景极窄且「实测支持时」难以操作化。保留最小搜索根纪律、「目录名不证明项目归属」与 `--hidden --no-ignore`（影响盘点完整性的正确性陷阱）。若未来实测发现模型乱用 `find` 或滥开并行，凭失败证据恢复相应细则。
- **Amp 的临时兼容 TODO 保持自然语言，不采用固定字段协议**（2026-08）：真实历史样本表明，固定 `trigger` / `action` 会把事实条件藏进 action，也会被 formatter 折行破坏；六字段卡片又会复写邻近代码和常规验证。消费单元是 TODO、邻近注释与代码。只要求补充 AI 无法从现场可靠推知的信息，并规定普通任务自然遇见相关 TODO 时查验或提醒，但不主动全仓巡检。

## 修改纪律

- 默认**只动结构和措辞，不动语义**；删减规则内容需用户逐条确认。
- 新增规则先过准入检验：它是**非显然的 invariant**（边界、身份、证据标准），还是 **how-to**（工具用法、操作步骤）？invariant 才有资格常驻本文件；how-to 优先做成 Skill 按需加载。每条常驻指令都应能说明自己修复了什么真实失败。
- 每次结构调整后核查：交叉引用（「除『Skill 冲突与反馈』一节另有规定外」）、scope 句与子节内容的对应、产物列表与子节顺序的一致。
- 本 README 与 AGENTS.md 同步维护：形成新共识、关闭待定项时更新本文件。

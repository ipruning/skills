# Snell PSK

部署、迁移、修复或验收客户端之前，先定下 PSK 从哪来。只有三种来源：

- 用户这次直接给的；
- 这次为这个目标新生成的；
- 用户点名让读的：某台 VPS 上的某个配置路径，或本机某个 Surge profile。

不去翻凭据缓存、密码管理器、无关 profile 或 shell 历史。PSK 不跨 VPS、账号或环境复用，也不借别的节点的值。读到一个 PSK，不代表能拿去配另一台服务端或客户端。

新 PSK 用独立的高熵值，只写进目标服务端配置和目标客户端 profile。交付走 `0600` 暂存文件、标准输入或应用自己的受保护配置入口。用暂存文件时先 `umask 077`，建好后立即注册 `EXIT` trap，成功失败都删掉。PSK 不进命令行参数、进程列表、journal、审计 JSON、host 清单、聊天和最终回复。写入时关掉 shell xtrace，不打印配置全文。

从 `psk = <value>` 这一行取值时，只去掉第一个 `=` 和它两边的空白，保留后面的完整原值，包括末尾的 `=` padding。不能按所有 `=` 分列再取第二段：这样会悄悄截掉 Base64 PSK 的 padding，而 Surge 的 TCP 延迟测试照样可能返回数值。所以判断 PSK 一致，还要看服务端没有对应的 `Decryption failed`，并且 UDP relay、出口 IP 或实际业务请求通过。

服务端和客户端要用同一个 PSK 时，从一个来源生成或读取一次，分别写进两个目标，中间不输出明文。找不到安全的交付路径就停下部署，向用户要来源或目标配置的入口。
